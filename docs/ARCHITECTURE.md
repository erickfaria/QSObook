# Implemented architecture

## Organization

A Go monolith: browser → `net/http` → `html/template` / SQLite operations → a local file. There is one `main` package, without an ORM, SPA or web framework. `main.go` composes configuration, storage and the HTTP server; `web.go` handles core HTTP, `web_rounds.go` composes the home/round workflows, `store.go` contains operator/contact persistence and validation, `rounds.go` manages round lifecycles, and `map.go` implements optional city lookup/cache operations. Templates, static assets, migrations, time-zone data and license notices are embedded in the executable. Callsign lookup requests stay local.

## SQLite driver and dependencies

`modernc.org/sqlite v1.36.3` is a BSD-3-Clause `database/sql` driver, a Go port of SQLite 3.49.0 without CGO, with documented Linux ARM64 support. It requires Go 1.23 and preserves the project declaration of Go 1.24.4. The standard library does not provide a SQLite driver. This choice avoids a C compiler and a system SQLite installation at the cost of a larger module tree and first compilation.

The [pinned version documentation](https://pkg.go.dev/modernc.org/sqlite@v1.36.3) includes platform support, licensing, changelog and upstream links. The pinned version is for reproducibility, not a claim that it is the latest release. Updates require reviewing Go compatibility, security notices, tests and migrations before distribution. CI checks reachable Go vulnerabilities with pinned govulncheck v1.9.0. No external security audit is claimed.

Runtime transitive dependencies are listed in `go.mod`: `modernc.org/libc`, `mathutil`, `memory`, `golang.org/x/sys`, `x/exp`, `github.com/google/uuid`, `dustin/go-humanize`, `mattn/go-isatty`, `ncruces/go-strftime` and `remyoudompheng/bigfft`. Their permissive BSD/MIT notices are retained in [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt), embedded and linked from the footer alongside the project AGPL. Original SQLite is public domain. `go.sum` also records dependencies used by upstream tests/tools. Keep `modernc.org/libc` aligned with the driver; do not update it independently.

Native Linux ARM64 builds and tests are supported without CGO. Local validation runs on Linux AMD64 with an ARM64 cross-build. GitHub Actions also tests and builds natively on hosted Linux AMD64/ARM64 runners using the Go version declared in `go.mod`; execution on Raspberry Pi remains pending.

## Data model

- `stations`: current operator registration with a nullable recoverable deletion timestamp, with a normalized unique callsign, name, city, state, country and permanent notes. A callsign identifies a station; no license verification or external lookup is performed.
- `qsos`: confirmed contacts with an independent recoverable deletion timestamp, linked to a station, with a UTC timestamp, mode, conversation notes and a historical copy of operator details. Registration edits do not change earlier contacts. Editing one contact changes only its copy; callsign and timestamp stay fixed.
- `rounds`: optional name, UTC start and optional end time. A partial unique index allows only one open roundtable. Closed sessions remain in storage; QSO mode lists the latest 50. Names and optional numeric editions distinguish roundtables from ordinary listening sessions.
- `participants`: round-scoped participation with its own mode, conversation notes, active/QRT state, optional confirmed QSO reference and optional removal timestamp. A partial unique index permits one visible participation per station per round. Removal hides the entry without deleting it. Participation IDs remain non-reusable.
- `app_settings`: map/home opt-in settings, a persistent bounded geocoding lease/cooldown and the last named roundtable/edition.
- `city_coordinates`: city/state/country keys with cached coordinates or a cached not-found result. The dashboard groups historical confirmed QSO locations, not current station locations.

New participant, manual QSO and registration forms only complete missing fields for existing callsigns. Saved nonempty values take priority over submitted data, including a stale lookup result. Replacing values requires an explicit edit by ID. Empty fields in a participation edit preserve the registration. Conversation notes never write permanent operator notes. The QSO entry form can separately fill missing permanent notes; replacing existing notes requires explicit registration editing. The registration editor permits intentionally clearing fields. Explicit concurrent edits still use the last saved values; no version conflict detection is implemented.

Adding someone does not confirm a contact. A repeated addition preserves the existing participation mode, notes and QSO reference; an explicit edit can change the mode or clear conversation notes. Participation writes and registration updates share one transaction. Editing a removed participation does not recreate it. QRT/return only changes presence. Ending a round retains its participants and confirmed contacts; it never confirms pending participants. New rounds reuse registrations and create independent participations. For another contact within a round, remove and add the operator again. Closed/removed participation actions are rejected before registration updates. Participant edits carry both round and participation IDs, so an old edit cannot reach a re-added operator. Closed round displays use current registration details, explicitly labeled as such; confirmed QSOs retain historical copies.

Confirmation uses a transaction to check the QSO reference, insert the historical copy and conversation notes, and link the QSO atomically. Repeated and simultaneous confirmations cannot duplicate a contact for that participation. Later registration or participation edits do not change the snapshot. The primary QSO entry saves registration, participation and optional confirmation together. A random 128-bit form key is checked before registration writes and has a partial unique index on confirmed QSOs. Replays return the earlier contact without changing its snapshot or a newer registration; reusing a key for another callsign is rejected. The older direct `POST /contact` API retains its previous new-contact semantics.

## Migrations and storage

SQLite uses one connection per process, `foreign_keys=ON`, `busy_timeout=5000` and its default rollback journal. No automatic data cleanup is performed. Migrations run in a transaction and use `PRAGMA user_version`; unknown future or invalid versions are rejected.

- `001_initial.sql` creates the original station, QSO and participant tables.
- `002_participant_identity.sql` retains all existing participant rows, IDs and QSO links while rebuilding that table with `INTEGER PRIMARY KEY AUTOINCREMENT`. Deleted participation IDs are not reused, including after restarts. Old record/remove forms return not found instead of affecting a new participation.

- `003_rounds.sql` adds named rounds, presence/removal state and QSO round references. A legacy live list becomes “Rodada anterior”, preserving records, links and the AUTOINCREMENT high-water mark even when the old list was empty.
- `004_map.sql` adds opt-in settings, a geographic coordinate cache and a QSO city index. It sends no network requests and leaves the map disabled.
- `005_records.sql` adds band, optional roundtable label and replay key to QSOs, optional band to participants and approximate home/auto-geocoding settings. It preserves records and IDs, copies existing round names into the new label, leaves unknown bands blank, preserves map consent and disables geocoding on save until selected.

- `006_data_tools.sql` adds nullable deletion timestamps/indexes to stations and QSOs without changing existing snapshots, links, replay keys or coordinates.
- `007_qso_workspace.sql` adds an optional round edition and remembered name/edition. Existing session names, contacts and presence state are unchanged; legacy editions start blank.

The complete migration commits only on success. Failure rolls back both data and schema changes. Migration tests cover retained operators, historical contacts, notes, links, ID sequence persistence, SQLite integrity, foreign keys and failure rollback. There is no automatic downgrade: copy the stopped database before upgrading and restart the updated application so old forms receive a new CSRF token.

The main database file is created with `0600` permissions and new directories with `0700`. Existing directory permissions are not changed. Main-file symlinks and non-regular files are rejected; use a trusted private directory. There is no encryption at rest. The default location is the user data directory; `-db` overrides it. Databases are never served as static files.

## Time, queries and validation

Timestamps come from the host clock and are stored in UTC with fixed-width nanosecond precision, allowing consistent textual sorting. `time/tzdata` embeds IANA time-zone data. Display uses `-timezone`, defaulting to `America/Sao_Paulo`. Manual timestamp editing is not available.

Callsigns accept 1–32 ASCII characters: letters, numbers, `/`, `.` and `-`, starting with a letter or number. Names and location fields allow 120 characters each; notes allow 4,000. Confirmed contacts require a mode of up to 40 characters. The QSO form offers local selectors and custom mode/band fields; band is optional. Country is an embedded CLDR dropdown with no default and preserves old free-text values. Country labels change with UI language while stored canonical names remain stable. Parameterized searches use `instr`, so SQL wildcard characters have no special meaning. A deterministic Go-backed SQLite scalar function folds common Latin accents and combining marks without modifying stored values. Stations and Notebook use 50-row pagination, matching counts and stable ordering; searches include city. Notebook date filters use inclusive local-calendar dates converted to UTC boundaries.

## HTTP and UI

The standalone server accepts loopback IPs only, defaulting to `127.0.0.1:8080`. Explicit `-container` additionally permits `0.0.0.0` inside a container network; Compose publishes only on host loopback and retains all HTTP security checks. External Host headers are rejected to reduce DNS rebinding risk. Writes use POST, a cryptographically random per-run CSRF token, constant-time comparison and Origin verification when present. The token does not authenticate users; old forms need reloading after a restart. Ordinary form bodies are limited to 32 KiB. The two file-upload endpoints allow a bounded multipart envelope and stream one file (64 MiB restore / 16 MiB ADIF) into private staging after the first CSRF part is verified; they do not spill to `/tmp`. HTTP header/time limits remain bounded. Mutable values come from the POST body.

`html/template` escapes values. CSP restricts resources to the local origin and blocks frames, inline scripts and external form submission. Only the opted-in home page additionally permits images from the configured tile origin. A Leaflet tile-image `referrerPolicy=origin` satisfies the tile provider requirement without sharing query paths or operator details; the global same-origin referrer policy omits Referer on other cross-origin requests. Responses set `nosniff`, `Referrer-Policy: same-origin`, frame protection and `Cache-Control: no-store`. Internal errors and form contents are not logged or shown to users. Standard server connection errors may appear in operational logs without application records. No security exception was introduced for screenshots or the integrated browser. Native form submissions need their real Origin: `no-referrer` instead produces `Origin: null` in browsers and breaks POSTs. The same-origin policy fixes that behavior without accepting null or external Origins. See the [MDN policy explanation](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy#effect_on_the_origin_header).

The main UI is a table with semantic HTML, labels and visible keyboard focus. The quick form and inline editors share compact fields; country and conversation notes use `details`. Mode and country are secondary cell information. Permanent and conversation notes are labeled separately. Edit links retain a separate-page fallback without JavaScript. Inclusion validation retains the submitted form and the participant table.

CSS adapts the QSO table to compact participant rows below 700px, with 44px touch targets. Other wide tables confine horizontal scrolling to their own regions. JavaScript debounces local `/lookup` requests, aborts older requests and checks a version counter after both the response and JSON parsing. This ignores stale responses and errors, including A → B → A changes. Edited fields are preserved and empty lookup values never clear fields. Drafts stay in memory per normalized callsign, without browser storage; blank callsigns do not revive an earlier unassigned draft. Lookup never copies permanent notes into a conversation.

JavaScript prevents repeated submission while a form is pending and restores controls on back navigation. SQLite provides the confirmation integrity guarantee; the UI guard is supplementary. Without JavaScript, registration, editing, queries and confirmation still work with manual entry. `tests/app.test.cjs` uses only built-in Node.js modules and a simulated DOM to test request ordering and form behavior.

The optional shared-password private-LAN configuration is described below. Individual user accounts and isolation are not implemented. The host clock, account security and private storage are deployment responsibilities. TLS, proxying or network exposure require a separate access-model decision. The optional map is the only external integration. Leaflet 1.9.4 (BSD-2-Clause) is vendored with its license and served locally. Script/style SHA-256 values match the official distribution. No npm packages, map plugins, Go dependencies or frontend framework were added.

## Round lifecycle and theme

Starting a round uses a transaction, the single-open-round index and the last known round ID to make repeated starts safe. Replaying a start after its round closed cannot silently open a new one. Ending a specific round is idempotent and cannot close a different round. Participant inclusion, editing, QRT and confirmation validate that their round is still open. Confirmation atomically copies the registration into `qsos` and associates the round. Closing a round performs no contact insertion.

Light/dark palettes use CSS variables. A small local head script applies the saved browser preference before rendering; system mode follows `prefers-color-scheme`. Only the theme preference uses localStorage. Contact drafts remain in page memory and are not written to browser storage. Storage failures leave the theme switch usable for the current page.

## Optional geographic services

The map is disabled by default and requires conscious opt-in with provider/privacy disclosure. Opening an enabled map requests only the final visible tile viewport. Browser HTTP caching is retained; there is no tile scraping, prefetching or offline download. Map markers and popup text come from local grouped contact data and use DOM text nodes, never operator-supplied HTML.

Each geocoding request requires an explicit POST for an existing confirmed-contact city or an explicitly opted-in location/confirmed-record save. Only city, state, country, format and result limit go to the provider. Names, callsigns and notes are excluded. Both coordinates and no-match responses are cached locally; an explicit correction/retry can revisit a not-found cache entry. Provider requests identify QSObook, have a three-second request-context deadline (inside the existing eight-second HTTP client timeout), do not follow redirects and have bounded JSON responses with finite/range-checked coordinates.

A SQLite lease serializes requests even across processes sharing the database. It expires after fifteen seconds if a process stops, and normal completion sets a further gap of at least 1.1 seconds. Error responses impose a cooldown and respect numeric/date Retry-After delays up to one day. Independent databases/instances require the operator to manage aggregate public-provider usage. No background geocoding, rendering/startup queries, autocomplete, periodic work or external callsign lookup is present. Geocoding on save runs after the contact transaction commits; provider errors or cooldowns leave the contact intact and its city pending for a later explicit action.

`-map-tiles-url` and `-geocoder-url` permit provider changes without a code update. HTTPS is required except for loopback HTTP services. Configuration is trusted operator input, never a request-supplied destination. Provider failure does not change contacts or registrations. The city list and contact history remain available without internet or JavaScript. See the [README](../README.md) for provider policy links and manual checks.


## Language preference and containers

`locale.go` loads embedded English, Spanish and French JSON catalogs once per application. Portuguese source phrases are the keys and default UI. Four immutable template sets bind translation to the request language; concurrent tabs cannot change another response's language. The `qsobook-language` cookie is written by a CSRF-protected POST, with a one-year lifetime, HttpOnly and SameSite=Lax. Only known local pages are accepted as return destinations. No language preference or translated content is written to SQLite.

An escaped JSON data attribute supplies the small browser-message catalog to the local `locale.js` helper. Dynamic messages use text nodes, including map popups and lookup feedback. No inline script, external translation API or CSP relaxation is needed. English dates use an unambiguous year-month-day format; other languages retain day/month/year. All languages use the configured time zone and the same stored UTC timestamps.

The multi-stage Dockerfile pins the official Go builder by tag and multi-architecture digest, uses CGO=0, and copies only the executable, CA certificates and a non-root-owned data directory into a scratch runtime. Build inputs use a `.dockerignore` allowlist to exclude databases, backups, environment files, Git metadata and caches. Compose supplies a persistent named volume, read-only root, temporary filesystem, no added capabilities and no-new-privileges. It introduces no application dependency or database migration. The CI smoke test uses its own randomly named project and synthetic data; cleanup removes only its disposable volume. See [DOCKER.md](DOCKER.md) for operation and limits.


## Optional private-LAN beta access

`access.go` preserves loopback Host handling and optionally adds an exact host:port allowlist. A password is optional. If configured, it requires a regular file containing 16–256 bytes; invalid files fail startup. Without it, the deployment network controls access. The process keeps only a SHA-256 comparison value; constant-time comparison protects password checking. This is an in-memory verification value, not a stored password database or password-derivation scheme. The authoritative plaintext secret stays in a private host directory and is mounted read-only as a Compose secret. The fixed Basic-auth username is `qsobook`; no accounts, database migration or external identity service are added.

When enabled, authentication runs before route execution, including static files, license endpoints and lookups. Disallowed Hosts are rejected before any password challenge. CSRF, exact same-host HTTP Origin validation and all frame/CSP policies remain unchanged. There are no shared sessions to synchronize; the browser handles Basic authentication, which has no app logout button. Unauthorized responses reveal no contact data or CSRF token. HTTP does not encrypt authentication: LAN mode is explicitly limited to a trusted network; use HTTPS/VPN for untrusted networks. Proxy/TLS trust handling is not added here.

`compose.release.yaml` uses a ready-made image on loopback. `compose.lan.yaml` requires a specific LAN/VPN IP and explicit host:port entries. `compose.auth.yaml` additionally requires a password secret. The default development Compose remains source-built and loopback-only. All use the same named data volume/project intentionally; choose one deployment, never parallel instances on the same notebook. Release downloads pin image digests. Only a manual release from main can publish after native AMD64/ARM64 tests, vulnerability checks and exact-image smoke tests; CI verifies stopped SQLite backup integrity as well as persistence. The publication signs GitHub provenance for the multi-architecture digest, then publishes prerelease assets and updates the opt-in beta channel. There is no server-side automatic update agent.

## Compact records, map and open assets

The primary navigation is Home, QSO mode and Notebook. QSO mode is the only entry workspace; `/records` renders it as a compatibility alias. Start a listening session with the roundtable checkbox off, or opt into a named roundtable with an optional edition. The database remembers the last named roundtable/edition without implicitly opting the next session in. Confirmation starts unchecked. Unconfirmed conversation notes stay in the participant draft; the explicit row action snapshots them into a QSO. An existing participation is not silently edited by re-adding it. QRT rows sort below active participants and use muted styling. Home has only small counts, a workspace link and the optional map. Light mode uses a white canvas with restrained pastel accents; dark/system themes remain available.

The monthly summary uses the calendar-month boundaries of the configured time zone, converted to UTC for comparison with stored timestamps. Map data groups cities locally with mode/band counts. Filters rebuild local markers and link to matching city history; they perform no geocoding. FM is blue, AM amber, digital red, SSB/CW separate muted colors and mixed groups neutral. A saved, cached home city gets a project SVG house marker. No street address, device location permission or personal operator data is sent externally.

Original SVG logo/home artwork and unmodified Atkinson Hyperlegible regular/bold WOFF2 fonts are served locally. CSS overrides vendor map-control font families. Font licenses are SIL OFL 1.1; extracted Unicode CLDR country names use Unicode License V3. Both licenses and pinned sources are retained in the third-party notices. No external font service, npm package, geospatial SQLite extension or new Go dependency is introduced. The country catalog is loaded once into immutable application memory rather than a SQLite table. Listings are paginated; explicit ordinary concurrent edits still use last-write-wins semantics.

## Data transfers and recoverable deletion

`backup.go` uses VACUUM INTO for a consistent SQLite snapshot, syncs the file/directory and validates schema, integrity, foreign keys and application metadata. Exact schema-5/6/7 uploads are inspected read-only before known migrations run in a separate staging copy; uploaded triggers/views/unknown schemas are rejected. `web_data.go` keeps one server-owned, expiring preview per instance. A database change stamp invalidates stale previews. Confirmation is serialized against HTTP operations; restoration first stores a validated durable recovery snapshot, then replaces known tables in a single transaction using a read-only attached source, deferred foreign keys and preserved sequences. The open SQLite file is never swapped. Old forms are invalidated by a fresh CSRF token. Passwords, host allowlists and provider configuration do not come from backups.

`trash.go` only changes nullable deletion timestamps. A station's unique callsign stays reserved, and archived operators cannot receive new contacts until explicitly restored. QSO snapshots, references and replay keys are retained. Read paths exclude trashed contacts from active notebook counts and map grouping. There is no permanent purge.

`adif.go` implements bounded ASCII ADI parsing and export with no additional dependency. A length-aware parser rejects malformed whole files, maps supported fields and discloses unsupported fields in the preview. `APP_QSOBOOK_DATA` preserves original UTF-8/custom snapshots in an ASCII base64 payload; other programs can ignore it. Import performs no geocoding, updates only missing registration fields and transactionally skips callsign/UTC-second/mode/band duplicates, including trashed QSOs. ADIF cannot replace the full SQLite backup. See [DATA.md](DATA.md) for operational and format limits.

`map_edit.go` updates only a selected saved city's coordinate cache, offline or via an explicit opt-in provider retry. A retry retains cached coordinates on failure/no-match and follows the existing database-backed provider cooldown. `version.go` exposes build metadata locally; release Docker builds pass a version and source revision. No automatic update check is introduced.
